## このRepoについて

`voice-gateway` は、TTS・STTエンジンを直接使うためのライブラリではなく、**複数の音声エンジンをエージェントや外部ツールから同じ形で扱うためのゲートウェイサーバー**である。

音声エンジンは、それぞれAPI形式、モデル指定、入出力の形式、実行方法が異なる。TTSエンジンのあるものは `voice` を文字列で指定し、別のものでは参照音声やlatentファイルを指定する。STTエンジンでも、対応オーディオ形式、言語指定、コールバックの有無などに差がある。

この差分をクライアント側に直接持ち込むと、エージェント、UI、通知処理などが、それぞれエンジン固有の事情を知る必要がある。

`voice-gateway` はその差分を吸収し、クライアント側からは次のように扱えるようにする。

**TTS（音声合成）:**

```json
{
  "model": "tts-default",
  "voice": "your-voice-name",
  "input": "こんにちは"
}
```

**STT（音声認識）:**

```bash
curl -X POST /v1/audio/transcriptions \
  -F "file=@audio.wav" \
  -F "model=stt-default"
```

つまり、このRepoの目的は **「音声エンジンを動かすこと」そのものよりも、「音声の出入口を安定したAPIとして固定すること」** である。

## なぜ必要か

AIエージェントに音声を持たせる場合、単にTTSを1回呼べればよいわけではない。また、エージェントがユーザーの音声を理解するためにはSTTも必要になる。

次のような問題が出てくる。

### TTS側

* OpenClawなど、OpenAI互換APIしか想定していないクライアントからローカルTTSを使いたい
* 自作エージェントからは、OpenAI互換にない独自パラメータも渡したい
* 特定の人格声を、TTSエンジンに依存しないIDとして管理したい
* Irodoriから別のTTSに変えても、クライアント側の設定をなるべく変えたくない
* TTSのCLI実行、timeout、tmpファイル管理、同時実行制御などをクライアント側に書きたくない
* 複数のエージェントやUIから、同じ音声生成口を使いたい

### STT側

* OpenAI互換APIを前提にしているツールから、ローカルSTTを使いたい
* 転写結果をコールバックで受け取り、非同期に処理したい
* 音声入力のバリデーション（形式・長さ・サイズ）をエンジンに依存させたくない
* 複数のSTTエンジンを同じAPI形式で切り替えたい

`voice-gateway` は、これらをまとめて受けるための薄い常駐APIサーバーである。

## どんな時に使うか

### OpenAI互換APIとしてローカルエンジンを使いたい場合

OpenClawなど、OpenAI互換のTTS APIを前提にしているツールから、IrodoriなどのローカルTTSを利用したい場合に使う。クライアント側は `baseUrl` を `voice-gateway` に向けるだけで、OpenAI互換TTSとして扱える。

同様に、OpenAI互換のTranscription APIを前提にしているツールから、ReazonSpeechなどのローカルSTTを利用したい場合にも使える。

### 自作エージェントに安定した音声入出力口を持たせたい場合

自作エージェントから直接Irodoriや各TTSエンジンを呼ぶのではなく、`/v1/audio/speech` を通して音声生成を行う。ユーザーの音声入力は `/v1/audio/transcriptions` でテキストに変換する。エージェント本体はエンジン固有の実行方法を知らなくてよい。

### 人格声を固定IDで管理したい場合

`voice_id` は、TTSエンジン固有の声指定ではなく、論理的な声IDとして扱う。たとえば `your-voice-name` というvoiceを、現在は [Irodori-TTS](https://github.com/Aratako/Irodori-TTS) の `ref_latent.pt` で実現し、将来は別のTTS Providerで実現する、といった運用が可能。

### エンジンを将来差し替えたい場合

最初はIrodoriを使い、将来Qwen-TTSや別のTTSエンジンを追加したい場合に、Providerとして拡張できる。STTについても同様に、ReazonSpeechから別エンジンへの差し替えが可能。クライアント側は `model` IDを使い続け、内部のProviderだけを切り替えることを目指す。

### TTSとSTTを別々のマシンで動かしたい場合

`VOICE_GATEWAY_MODE` 環境変数で `tts` / `stt` / `all` を選べる。GPUが載ったWindowsマシンでは `mode=tts`（Irodori）、軽量ミニPCでは `mode=stt`（ReazonSpeech）のように、異なる環境で同じコードベースを用途別に起動できる。

## 使わないほうがよいケース

このRepoは、すべての音声用途に向いているわけではない。

次のような場合は、音声エンジンを直接使ったほうが単純である。

* 1つの音声エンジンだけを、単発のスクリプトから呼べればよい
* OpenAI互換APIが不要
* voice / model / provider を分離して管理する必要がない
* エージェントや複数クライアントから共通利用する予定がない
* CLIで手動生成できれば十分
* リアルタイムストリーミング（WebSocket等）が必要

`voice-gateway` は、単発の音声処理ツールではなく、**エージェントシステム向けの音声入出力レイヤー**として使うことを想定している。
